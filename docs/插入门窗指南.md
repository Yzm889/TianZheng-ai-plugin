# 门窗插入：为什么必须点鼠标，以及怎么点

> 这篇文档记录的是**实测结论**，不是推测。每条都有对应的实验证据。

## 结论先行

天正门窗（`TDbOpening`）**只有在 `MC` 命令里用鼠标点选插入到墙上**时，才会和墙
建立宿主关系并自动在墙上开洞。任何"自动化"的替代方案都不成立：

| 尝试 | 结果 | 证据 |
|---|---|---|
| 用 COM 复制已有门窗（模板克隆） | ❌ 外观正确，**墙不开洞** | 墙 `445` 始终是完整一段 12000~20400，没有被切分 |
| 把复制出的门窗 `Move` 到墙轴心线 | ❌ 图形对齐了，墙仍是实心 | 移动前后墙段数都是 1 |
| `TValidOp`（门窗检查）重建宿主关系 | ❌ 无效 | 输入 `ALL` 后触发 `PLAY` 命令，墙段数不变 |
| 调 `tch_kernal.arx` 的 `insertIntoWall` | ❌ 进程外不可行 | 该 ARX `LoadLibrary` 失败（缺 ObjectARX 依赖）；且符号不是标准导出 |
| 用第三方 DLL（CodexAutoCadMcpBridge） | ❌ 不能给所有人用 | 句柄硬编码在作者图纸里；也不能重新分发别人的编译产物 |

**根本原因**：`MC` 的插入点只接受鼠标点选，不接受坐标输入。输入 `1500,0` 会被当成
命令执行，报"未知命令"。

## 正确的操作流程

插入门窗助手（`opening_assist.py`）把这一步降到"照着点几下"：

### 1. 生成点击清单

插件按规格算好每个门窗的插入点（**落在墙轴心线上**），并给每个点画可捕捉的锚点。

```python
from t20_arch_mcp import opening_assist

items = [
    {"kind": "door",   "x": 16200, "y": 7800, "width": 1500, "label": "M1"},
    {"kind": "window", "x": 13800, "y": 0,    "width": 1800, "label": "C1"},
]
plan = opening_assist.make_plan(items)      # 序号/坐标/宽度/类型
opening_assist.mark_on_drawing(items)       # 在图上画锚点
```

或者用自然语言指令：

```
插入门窗助手
```

### 2. 每个锚点由什么组成

`mark_on_drawing` 在 `AUX-OPENING` 图层上给每个插入点放 4 个对象：

| 对象 | 作用 |
|---|---|
| **短线**（`±60`） | **中点**就是插入点 → 用【中点】捕捉精确命中 |
| **POINT** | 用【节点】捕捉 |
| 圆环 | 视觉提示，方便找 |
| 序号文字 | 标注第几个点 |

> 第一版只画了圆圈和十字，**不能捕捉**，用户反馈"标注点不能拾取"后改为现在的方案。

### 3. 用户操作（关键）

**先开捕捉**：

```
OSNAP 回车 → 勾选【中点】和【节点】 → 确定
```

**然后**：

```
MC 回车
  ├─ 门：直接回车确认（默认就是门）
  └─ 窗：先点对话框底部工具栏第 2 个【窗】图标，再回车

鼠标移到短线的中间，出现"中点"提示时点击
按序号顺序点完全部
回车结束
```

### 4. 核对结果

```python
opening_assist.verify(items)     # 检查每个预期位置是否真的有门窗
opening_assist.clear_marks()     # 删除所有辅助标记
```

`verify` 返回 `found` / `missing_steps`，能精确指出漏了第几个点。

## 踩过的坑（都别再犯）

1. **包围盒中心对齐墙线 ≠ 正确** —— 门的包围盒包含开启弧，中心不在门框上
2. **底边/顶边贴墙面也 ≠ 正确** —— 图形对齐了，但墙不开洞
3. **必须落在墙轴心线** —— 这是让墙自动开洞的唯一条件
4. **`ScaleEntity` 改不了门窗宽度** —— 只改高度，宽度是天正内部参数
   （宽度也读不回来：XData 是空的、没有 Width 属性、包围盒把宽度和高度混在
   一起。所以要不同宽度，就先建不同宽度的模板，再用
   `register_opening_template(句柄, 宽度)` 登记一次；`build_plan` 会按登记宽度
   匹配，匹配不上就告诉你要建哪一樘，不会拿错宽度的模板凑数）
5. **圆形/十字标记不可捕捉** —— 必须用有线段的图形（中点/端点）

## 自动化边界

天正把"插入门窗"做成了纯交互命令。在**不逆向、不分发第三方 DLL**的前提下，
插件能做的极限是：

- ✅ 算准每个点该插在哪
- ✅ 画出可捕捉的锚点
- ✅ 核对有没有漏
- ❌ 代替用户点鼠标

这是天正的架构决定的，不是插件能力不足。这条边界对所有用户一致，所以
"所有人都能用"这个目标仍然成立。
